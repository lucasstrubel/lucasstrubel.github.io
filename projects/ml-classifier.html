Case Study

ML Text Classifier

Python Scikit-learn FastAPI NLP Machine Learning
View on GitHub

Overview

This project is an end-to-end machine learning pipeline for classifying short text into predefined categories. It covers the full lifecycle: data preprocessing, feature extraction, model selection, evaluation, and deployment as a lightweight REST API using FastAPI.

The aim was not just to train a model, but to deliver something that could actually be called from another application — treating the classifier as a service rather than a notebook experiment.

The Problem

Manually categorising large volumes of short text — support tickets, survey responses, product reviews — is time-consuming and inconsistent across different people. An automated classifier that can pre-sort incoming items into buckets dramatically reduces the triage effort.

The challenge was balancing model accuracy against inference speed. A REST API needs to respond in milliseconds, which ruled out heavier transformer-based approaches in favour of fast, well-tuned classical models.

Approach & Methodology

The pipeline uses TF-IDF vectorisation with an n-gram range to capture short phrases, fed into a Logistic Regression and a Linear SVC. Both were evaluated with cross-validation before selecting the better performer per dataset.

  • Text cleaning: lowercasing, stopword removal, punctuation stripping
  • TF-IDF (1–2 gram range) — fast to compute, interpretable weights
  • Logistic Regression vs. LinearSVC compared on F1-macro score
  • FastAPI wraps the trained model — single POST /predict endpoint
  • Model serialised with joblib so it loads in milliseconds on startup

Key Findings & Outcomes

  • LinearSVC outperformed Logistic Regression by ~4% F1-macro on the test set
  • Average API response time under 12ms — suitable for real-time use
  • Exposing the model as an API rather than a script made it immediately reusable by other projects
  • Feature importance analysis revealed that model was picking up on writing style signals, not just topic keywords — useful insight for future data collection

Reflection

The most valuable part of this project was building the API wrapper. Turning a trained model into a callable service is a different skill from training the model itself, and it forced me to think about input validation, error handling, and versioning in a way that a standalone script doesn't.

The natural next step would be adding an active learning loop — flagging low-confidence predictions for human review and retraining on the confirmed labels — to improve accuracy over time without a full labelling effort.
