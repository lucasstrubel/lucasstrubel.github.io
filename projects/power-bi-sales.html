Case Study

Power BI Sales Dashboard

Power BI DAX SQL Server Data Modelling Data Visualisation

Overview

This project involved building an end-to-end sales analytics solution for a fictional retail company. Starting from raw transactional data in SQL Server, I designed the data model, wrote the business logic in DAX, and delivered a multi-page Power BI report aimed at both operational managers and senior leadership.

The goal was to replace a slow, error-prone Excel reporting process with a live, drill-through dashboard that could be filtered by region, product category, and time period — all updating in under two seconds.

The Problem

The sales team was working with a manually updated Excel workbook that took over two hours to refresh each Monday morning. Formulas broke regularly, different versions circulated across teams, and there was no way to drill into the numbers without asking for a custom export.

Key pain point: leadership had no single source of truth for YTD revenue vs target, and regional managers couldn't self-serve their own performance data.

The brief was to build something that non-technical stakeholders could open each morning and immediately understand — no training required.

Approach & Methodology

I started by auditing the source data in SQL Server — identifying data quality issues, understanding the grain of each table, and mapping out the relationships needed for the star schema.

Data transformation was handled in Power Query before loading into the model, keeping the DAX layer focused purely on business logic rather than data cleaning.

The DAX measures follow a consistent naming convention and are grouped into display folders — base measures, ratio measures, and time intelligence measures (MTD, QTD, YTD, same period last year). This made it easy to audit and extend the model later.

  • Star schema with one fact table (Sales) and four dimensions (Date, Product, Region, Customer)
  • All date intelligence via a dedicated, contiguous Date table marked as the model's date table
  • Row-level security configured for regional managers
  • Report-level measures separated from model measures to avoid clutter

Key Findings & Outcomes

The finished report consists of four pages: Executive Summary, Regional Breakdown, Product Performance, and a Detail page for drill-through on individual transactions.

  • Reduced Monday morning reporting time from 2+ hours to zero — report refreshes automatically via scheduled gateway
  • Identified the North region was consistently 12% below target due to a single underperforming product category not previously visible in the Excel report
  • Leadership adopted the Executive Summary page as the default opening view in weekly business reviews
  • Three regional managers began using the drill-through feature daily within the first week of rollout

Reflection

The biggest challenge was convincing stakeholders to trust a live report over a familiar spreadsheet. A short demo session where I showed the drill-through capability — something impossible in Excel — was what shifted the conversation.

If I were to extend this project, I'd add a forecasting page using the built-in Power BI Analytics pane, and explore embedding the report directly into a Teams channel so stakeholders receive proactive alerts when revenue drops below a threshold.

This project reinforced that the technical work (DAX, modelling) is often the easier half — the harder half is understanding what questions the business actually needs to answer.
