Case Study

Interactive Data Dashboard

Python Pandas D3.js Data Visualisation Analysis
View on GitHub

Overview

This project is an interactive analytics dashboard built entirely in Python, combining data processing with a browser-based visualisation layer. The goal was to take raw, messy datasets and surface trends in a way that anyone — regardless of technical background — could explore and understand.

Rather than a static chart, the dashboard allows filtering, drilling into sub-categories, and comparing time periods — turning a passive report into an exploratory tool.

The Problem

The source data was spread across multiple CSV exports with inconsistent column names, mixed date formats, and missing values. Producing a reliable view of it required a repeatable cleaning pipeline rather than manual fixes every time the data was refreshed.

Core challenge: build something that could be refreshed with new data in one command — no manual steps, no broken formulas.

Approach & Methodology

The pipeline is split into three stages: ingest, transform, and render. Pandas handles all data cleaning and aggregation. The output is a structured JSON that feeds the D3.js frontend, keeping the two concerns cleanly separated.

  • Automated column normalisation and type coercion on load
  • Missing value strategy documented per field — impute, drop, or flag
  • Aggregations computed in Python so the frontend stays lightweight
  • D3 charts are reusable components — same chart type, different data

Key Findings & Outcomes

  • Reduced data preparation time from ~45 minutes of manual work to a single script run
  • Identified an outlier cluster in the data that had been hidden by monthly aggregation in the original reports
  • The reusable chart components were later adapted for a separate project with minimal changes

Reflection

The biggest lesson was investing time upfront in the cleaning pipeline rather than patching issues later. Every hour spent making the ingest stage robust saved multiple hours downstream.

If I extended this project, I'd add a simple web server so the dashboard can be shared via a link rather than run locally, and introduce a configuration file so non-technical users can point it at different datasets without touching the code.
